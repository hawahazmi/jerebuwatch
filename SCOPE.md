# JerebuWatch — Malaysia Haze Monitoring Dashboard
**Project Scope Document v1.0** | Prepared: 31 Aug 2026 | Owner: Amalin Hawa
**Purpose:** Passion project + BI/data-storytelling portfolio piece, with real public-health awareness impact during Malaysia's 2026 haze season (Super El Niño year).

---

## 1. Problem Statement
Malaysia is in an active, worsening transboundary haze crisis (Aug 2026): API readings above 200 ("very unhealthy") in Sarawak, 100+ school closures affecting ~200,000 students, URTI cases up 124% and asthma up 259% week-on-week, with experts warning of 2015/1997-level severity due to El Niño. The public checks air quality daily but has no single, beautiful, story-driven dashboard that connects **what the air is doing → why (cross-border hotspots) → what to do about it**.

## 2. Objective
Build and publicly deploy a free, static, mobile-friendly dashboard that:
1. Shows current and historical air quality across Malaysia (station + modelled data)
2. Visualises the transboundary cause: hotspot locations and wind/smoke transport from Sumatra & Kalimantan
3. Tells the human impact story: health spikes, school disruptions, historical haze-year comparisons
4. Gives plain-language daily guidance ("today's risk level & precautions")

## 3. Target Users
- **Primary:** Everyday Malaysians checking daily air quality (especially Klang Valley, Sarawak, Johor residents)
- **Secondary:** Parents (school closure decisions), teachers, journalists, health-conscious users
- **Tertiary:** Recruiters/analysts viewing this as a portfolio artifact

## 4. Scope

### IN SCOPE (MVP)
| # | Feature | Data Source |
|---|---------|-------------|
| F1 | Current air quality map of Malaysia — station-level AQI with colour-coded markers | Open-Meteo AQ API (modelled, verified working) + APIMS scraping (official, stretch) |
| F2 | City/station drill-down: 7-day and 30-day PM10/PM2.5 time-series charts | Open-Meteo (hourly, free, no key) |
| F3 | Historical haze context: 2015 vs 2019 vs 2026 severity comparison | Kaggle/data.gov.my historical API dataset (2005–2017) + APIMS scrape (2018+) |
| F4 | "Why is this happening" panel: Indonesia hotspot count map + wind direction arrows | NASA FIRMS (free API key) + Open-Meteo weather/wind API |
| F5 | Daily guidance card: risk level + 3 plain-language precautions (BM + EN) | Derived from AQI thresholds — static content, no data needed |
| F6 | About/methodology page: sources, limitations, license (CC BY attribution), last-updated timestamp | Static |
| F7 | **Telegram bot:** daily brief 6:30 AM MYT, per-area subscription (pick state/city), threshold alerts (ping when area crosses unhealthy level). Fully automated via GitHub Actions hourly cron → Telegram Bot API. No phone numbers collected (PDPA-free). | Open-Meteo + APIMS data pipeline → Telegram Bot API (free) |
| F8 | **WhatsApp Channel:** same daily brief as F7, posted manually each morning (no official posting API — by design). Reach amplifier for demographics not on Telegram. | Generated by the same pipeline; manual 30s post |

### OUT OF SCOPE (do not build in MVP)
- Social media sentiment / public perception analysis (killed deliberately — data acquisition wall)
- Predictive/forecasting ML models (v2 candidate only)
- Mobile app / PWA install
- User accounts, notifications, push alerts
- Real-time streaming (<hourly) — daily refresh is sufficient for static hosting

### V2 CANDIDATES (only if MVP ships and motivation survives)
- 14-day smoke outlook (simple heuristics, NOT ML)
- Health impact layer: KKM URTI/asthma weekly stats if publishable
- Photo essay layer: personal haze photography with the story (ties in photography interest)
- BM/EN toggle polish, Telegram bot for daily briefings

## 5. Data Architecture (verified 31 Aug 2026)

| Source | Status | Access Method |
|--------|--------|---------------|
| Open-Meteo Air Quality API | ✅ TESTED LIVE — no key, free | REST, hourly PM10/PM2.5, any lat/lon |
| Open-Meteo Weather API | ✅ Free, no key | Wind speed/direction for smoke transport arrows |
| APIMS (DOE official) | ⚠️ No public API | Scrape station readings (Devin task); cache to JSON |
| NASA FIRMS hotspots | ⚠️ Free registration needed | API key → daily hotspot CSV for Sumatra/Kalimantan bbox |
| data.gov.my `air_pollution` | ⚠️ Stale (to 2022) | CSV download, historical context only |
| Kaggle Malaysia API dataset | ✅ Downloadable | 2005–2017 historical baseline |

**Pipeline:** GitHub Actions workflow (daily cron, e.g. 06:00 MYT) → fetch all sources → transform/clean with Python → write `/data/*.json` → commit → Vercel auto-redeploys. Idempotent and resumable by design.

## 6. Tech Stack
- **Frontend:** Static HTML/CSS/JS (or Next.js static export) + **ECharts** for charts + Leaflet for the map
- **Language:** English-primary with BM key terms; mobile-first design
- **Hosting:** Vercel (proven — DengueIt deployed there) — free tier
- **Data pipeline:** Python 3.10+, GitHub Actions cron
- **Dev workflow:** Devin AI for scaffolding/pipeline code; Amalin owns requirements, data QA, chart design, and narrative
- **Repo:** GitHub, public (portfolio value)

## 7. Success Criteria (Definition of Done for MVP)
1. Deployed on Vercel with a clean URL, loads in <3s on mobile
2. Map shows air quality for ≥10 Malaysian locations with correct colour coding
3. At least one city drill-down with 30-day trend chart
4. Historical comparison section showing 2015 vs 2026
5. Hotspot map with at least one successful FIRMS data pull
6. Methodology page with all source attributions and a last-updated timestamp
7. GitHub repo with README written as a portfolio case study (problem → approach → stack → limitations)
8. One shareable post (LinkedIn/X) announcing launch

## 8. Risks & Mitigations
| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| APIMS scraping breaks (site changes) | High | Open-Meteo is the backbone; APIMS is enhancement only |
| FIRMS key registration delayed | Low | F1/F2 ship first; hotspot panel is F4 |
| Motivation decay mid-build | Medium | MVP strictly capped; pipeline automated day one; phases below |
| Data accuracy criticism (modelled vs official) | Medium | Prominent methodology disclaimer; modelled data clearly labelled |
| Haze season ends before launch | Medium | Ship minimal MVP fast; historical comparison gives year-round relevance |
| Reach gap: most-exposed users (riders, outdoor workers) don't visit dashboards | High | F7/F8 notification layer pushes the daily brief to them directly; dashboard drives sign-ups via shareable cards |

## 8.5 Ambition Assessment & Anti-Stall Plan (locked 31 Aug 2026)

**Verdict:** Project is technically BELOW the owner's proven ceiling (hackathon champion app, BiLSTM FYP, BNM Power BI dashboard). The real risk is schedule/structure, not capability. Full 8-feature scope is too heavy for solo "whenever I feel like it" energy; MVP is therefore re-cut below.

**MVP redefinition — "The Air Brief" (ship line = 3 features):**
- F1 map + F2 one-city drill-down + F5 guidance card + methodology page (F6).
- Everything else (F3 historical, F4 hotspots, F7 Telegram, F8 WhatsApp Channel) is POST-LAUNCH, not MVP.

**Pre-committed cut list (if energy dips):**
1. First cut: F8 WhatsApp Channel (daily manual chore)
2. Second cut: F3 historical comparison (tedious data alignment)
3. Never cut: F1/F2/F5/F6 — the spine.

**Anti-stall rules:**
- Minimum viable rhythm: ONE 90-minute session per week, same day, calendar-blocked. Bad sessions count.
- Automate the data pipeline (Phase 0) before any visual polish.
- Devin scope: mechanical tasks only (scaffold, API calls, charts). Devin NEVER adds features. All scope decisions belong to Amalin.
- Public accountability: one "building in public" update per phase completion.
- Known non-differentiators: waqi.info/APIMS already show air quality. Positioning must lead with the narrative layer, BM/EN shareable briefs, and notification reach — not raw data.
- Hotspot framing stays data-neutral (numbers, not blame) to avoid diplomatic spillover.
